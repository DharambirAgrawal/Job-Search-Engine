# Job Search Engine

![Node.js](https://img.shields.io/badge/Node.js-Express%205-339933?logo=node.js&logoColor=white)

A skill-matching backend that pairs candidates with jobs using set-similarity algorithms, an inverted-index search engine, and a graph model of how skills relate to one another.

## Overview

Job Search Engine is a full-stack demo of the core mechanics behind a job board's matching logic, built from scratch rather than delegated to a database's built-in search or a third-party matching API. Users and jobs are modeled as skill sets; a Jaccard-similarity engine ranks jobs against a candidate's profile, a hand-rolled inverted index powers keyword search, and a directed skill graph drives recommendations and "upskilling path" lookups (e.g. what to learn to get from `React` to `Angular`). An optional Google Gemini integration layers AI-generated explanations, learning plans, and resume-to-job fit analysis on top of the deterministic graph logic, with graceful fallback when no API key is configured.

## Features

- **Skill-based job matching**: ranks jobs for a user with Jaccard similarity and a simpler overlap-based score
- **Inverted-index search**: tokenizes job titles, descriptions, companies, and skills into a custom index for fast keyword search, with a database-backed fallback
- **Skill graph**: a directed, weighted graph of skill relationships used to recommend next skills to learn and to find a shortest learning path (BFS) between two skills
- **Resume advisor**: upload a PDF resume (`pdf-parse`), extract skills via keyword matching, and get coverage/gap analysis against a job description or existing job listing
- **AI-enhanced insights (optional)**: when `GEMINI_API_KEY` is set, skill recommendations, learning paths, and job-fit analysis (strengths, gaps, priority skills, a tailored pitch) are generated by Gemini instead of the graph-only fallback
- **REST API**: full CRUD for users and jobs, plus dedicated matching, search, skills, insights, and advisor endpoints
- **React frontend**: a single-page client (React Router, dark/light theme) for exercising every feature, including managing users and jobs, running matches, searching, exploring the skill graph, and running AI insights

## Tech Stack

- **Backend:** Node.js, Express 5
- **Database:** NeDB (embedded, file-based, MongoDB-style query API) via a small custom model layer
- **Frontend:** React 19, React Router 7
- **AI:** Google Gemini (`@google/generative-ai`), optional
- **Other:** Multer + pdf-parse (resume upload/parsing), Axios, dotenv

## How It Works

- **Matching (`services/matcher.js`)** computes Jaccard similarity (`|intersection| / |union|`) and a simpler required-skill overlap score between a user's skills and a job's required skills, then ranks and returns the top matches.
- **Search (`services/search.js`)** builds an in-memory inverted index on every search call, mapping each token in a job's title, description, company, and skills to the job IDs containing it, then scores jobs by how many query tokens they match. Falls back to a direct database text search if index construction fails.
- **Skill graph (`services/skillGraph.js`)** stores skills as nodes in a directed, weighted adjacency list (e.g. `JavaScript → React`, `Node.js → Express`) seeded with common relationships. It answers two questions: "what should I learn next?" (weighted neighbor aggregation) and "how do I get from skill A to skill B?" (breadth-first search over the graph). Both fall back to this graph-based logic when Gemini isn't configured.
- **Resume advisor (`api/routes/advisor.js`)** parses an uploaded PDF, extracts a fixed vocabulary of technical skills via keyword matching, tokenizes both resume and job text for term-frequency analysis, and computes coverage/gap/seniority signals, all without AI. If `useAI=true` and Gemini is available, the same skill sets are passed to Gemini for a structured job-fit write-up.

## Getting Started

### Prerequisites

- Node.js v18+

### Installation

```bash
git clone https://github.com/DharambirAgrawal/Job-Search-Engine.git
cd Job-Search-Engine
npm install
```

### Configuration

Copy the example environment file and adjust as needed:

```bash
cp .env.example .env
```

| Variable         | Description                                                            |
| ---------------- | ------------------------------------------------------------------------ |
| `PORT`           | Port the API server listens on (default `3000`)                         |
| `NODE_ENV`       | `development` or `production`                                           |
| `DB_TYPE`        | Database mode (`local` uses file-based NeDB)                            |
| `GEMINI_API_KEY` | Optional. Enables AI-enhanced recommendations, learning paths, and job-fit/resume insights. Get one at https://aistudio.google.com/ |

### Seed sample data (optional)

```bash
npm run seed
```

Populates the local database with a handful of sample users and jobs so the matcher, search, and skills endpoints have data to work with.

### Run the API

```bash
npm run dev    # with nodemon, auto-restart on changes
npm start      # plain node
```

The API listens on `http://localhost:3000` by default.

### Run the frontend (development)

```bash
cd frontend
npm install
npm start
```

This starts the React dev server separately (typically on port 3000 with a proxy, or configure `REACT_APP_API_URL` as needed). For a single-server setup, build the frontend and let Express serve it:

```bash
npm run react-build   # builds frontend/build and reinstalls backend deps
npm start             # Express serves frontend/build at /
```

## API Reference

| Method | Route                         | Description                                |
| ------ | ------------------------------ | ------------------------------------------- |
| POST   | `/api/users`                   | Create a user with skills                   |
| GET    | `/api/users`                   | List all users                              |
| GET    | `/api/users/:id`                | Get a user by ID                            |
| PUT    | `/api/users/:id`                | Update a user                               |
| DELETE | `/api/users/:id`                | Delete a user                               |
| POST   | `/api/jobs`                    | Create a job listing                        |
| GET    | `/api/jobs`                    | List all jobs                               |
| GET    | `/api/jobs/:id`                 | Get a job by ID                             |
| PUT    | `/api/jobs/:id`                 | Update a job                                |
| DELETE | `/api/jobs/:id`                 | Delete a job                                |
| GET    | `/api/matcher/match/:userId`    | Ranked job matches for a user               |
| GET    | `/api/search?q=term`            | Keyword search over jobs                    |
| GET    | `/api/skills`                   | List all skills in the graph                |
| GET    | `/api/skills/related/:skill`    | Related skills for a given skill            |
| GET    | `/api/skills/recommend`         | Recommend next skills to learn              |
| GET    | `/api/skills/path`              | Find a learning path between two skills     |
| POST   | `/api/insights/job-fit`         | AI job-fit analysis (requires Gemini)       |
| POST   | `/api/advisor/analyze`          | Resume/job-description skill-gap analysis, with optional AI enhancement |
| GET    | `/api/health`                   | Health check, reports AI availability       |

### Example: add a user

```bash
curl -X POST http://localhost:3000/api/users \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice Smith", "skills": ["JavaScript", "React", "Node.js", "HTML", "CSS"]}'
```

### Example: match a user to jobs

```bash
curl http://localhost:3000/api/matcher/match/<userId>
```

### Example: AI job-fit analysis

```bash
curl -X POST http://localhost:3000/api/insights/job-fit \
  -H "Content-Type: application/json" \
  -d '{
    "userSkills": ["JavaScript", "React", "Node.js"],
    "jobSkills": ["React", "TypeScript", "GraphQL"],
    "jobTitle": "Frontend Engineer",
    "company": "Acme"
  }'
```

Returns `503` with a descriptive message if `GEMINI_API_KEY` isn't configured.

## Deployment

The repo includes a `Procfile` and `render.yaml`, configured for a single web process (`node api/server.js`) with a `/api/health` health check, suitable for Render, Heroku, or any similar platform-as-a-service.
